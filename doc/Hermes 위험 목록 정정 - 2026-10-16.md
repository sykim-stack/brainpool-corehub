# Hermes 위험 목록 정정

- 기준일: 2026-10-16
- 기준 코드: CoreHub PR #2, `security/corehub-event-integrity-2026-10-05`, HEAD `2ba2370`
- 상태: 조사 결과 정정본

## RISK-001: CoreNull → CoreHub Fact 계약 불일치

- **심각도:** blocker
- **상태:** confirmed
- **영향:** CoreHub PR #2는 검증된 Supabase Bearer token과 `Idempotency-Key`를 요구하지만, CoreNull의 현재 `pushFact()`는 `Content-Type`만 보내고 `owner_key`를 body에 넣는다. 현재 경로로는 Fact가 정상 처리되지 않으며, 운영 송신을 시작할 수 없다.
- **CoreHub 증거:** `app/api/corehub/facts/route.js:16-23, 76-100`; `lib/corehub/auth.mjs:8-33`
- **CoreNull 증거:** `app/api/corenull/rooms/route.js:3-10`; `app/api/corenull/posts/route.js:3-11`
- **정정:** “CoreHub facts API가 개방됨”이 아니다. CoreHub consumer 계약은 구현되어 있으나 CoreNull producer가 계약을 충족하지 않는다.
- **권고:** Auth UID/ownership 경로와 worker 인증을 결정한 뒤 CoreNull outbox worker를 구현한다.
- **운영 적용:** no — approval required

## RISK-003: fire-and-forget Fact 유실

- **심각도:** high
- **상태:** confirmed
- **영향:** 네트워크 오류, CoreHub 503, 배포 중단 또는 request 종료 시 Fact가 durable하게 남지 않고 소실된다. 현재 `fetch(...).catch(() => null)`은 실패를 호출자에게 전달하지 않는다.
- **증거:** `brainpool-corenull/app/api/corenull/rooms/route.js:5-10`; `posts/route.js:5-11`
- **권고:** 도메인 mutation과 같은 transaction에서 durable outbox row를 기록하고, worker가 retry/backoff/lease/quarantine을 수행한다.
- **운영 적용:** no

## RISK-007: stable idempotency key와 domain revision 부재

- **심각도:** high
- **상태:** confirmed
- **영향:** 현재 Fact에는 stable event key, payload hash, monotonic domain revision이 없다. 재시도 시 동일 이벤트 판별이 불가능하고, 동일 key에 다른 payload가 매핑되는 producer 오류를 예방할 수 없다.
- **증거:** `brainpool-corenull/app/api/corenull/rooms/route.js:128`; `posts/route.js:138-148, 271-280`; `brainpool-corenull/lib/database.types.ts`의 관련 table 타입에는 `version`/`revision` 없음
- **대조:** CoreHub PR #2는 `Idempotency-Key`를 필수로 받고 동일 key의 다른 이벤트를 `409`로 거부한다(`app/api/corehub/facts/route.js:76-79, 148-150`). 문제는 CoreNull producer가 아직 해당 계약을 생성하지 않는 것이다.
- **권고:** domain revision 또는 transaction-bound event sequence를 정하고, canonical payload hash와 stable idempotency key를 outbox에 저장한다.
- **운영 적용:** no

## RISK-008: worker 인증·ownership assertion 미결정

- **심각도:** blocker
- **상태:** confirmed
- **영향:** CoreHub PR #2는 Bearer token에서 `user.id`를 유도하고 `house_id` ownership을 검증한다. 그러나 CoreNull worker는 사용자 access token 보관·갱신 경로가 없고, `owner_key`를 Auth UID로 사용할 수 없다. 서비스 인증을 선택하더라도 signed ownership assertion과 key rotation 계약이 아직 없다.
- **증거:** `brainpool-corehub/app/api/corehub/facts/route.js:97-134`; `brainpool-corehub/lib/corehub/auth.mjs:8-33`; `brainpool-corenull/app/api/auth/google/route.js:34-80`; `brainpool-corenull/hooks/useGoogleLogin.ts:66-75`
- **권고:** 사용자 위임 token 또는 HMAC/mTLS 서비스 인증 중 하나를 ADR로 승인하고, `house_id → verified owner_id` 검증 방식을 별도로 확정한다. `service_role`을 사용자 identity assertion으로 사용하지 않는다.
- **운영 적용:** no — approval required

## 판정

CoreHub PR #2의 consumer-side integrity 계약은 구현되어 있다. 남은 blocker는 CoreNull producer의 Auth UID/ownership/outbox/worker 통합이다. PR #2를 “개방 API 수정”으로 설명하지 않고, **계약 소비자는 준비되었으나 생산자가 아직 연결되지 않은 상태**로 기록한다.
